## 📖 О проекте

**Hakchi3** — это неофициальный, полностью русифицированный форк популярной утилиты **Hakchi2-CE** (Community Edition), предназначенной для модификации и расширения возможностей ретро-консолей **NES Classic Edition**, **SNES Classic Edition** и **Sega Genesis/Mega Drive Mini**. Проект базируется на версии **v3.9.3** оригинального Hakchi2-CE от TeamShinkansen и поддерживается независимым разработчиком.

> ⚠️ **Внимание**: Это **не официальный релиз** от команды TeamShinkansen. Все права на оригинальный код принадлежат их авторам, ClusterM и TeamShinkansen.

### 🌟 Ключевые особенности


-   **🚀 Переход на современную платформу .NET8** — кодовая база мигрирована на более новую версию .NET, что обеспечивает лучшую производительность и совместимость.
-   **🔧 Обновление и замена уязвимых NuGet-пакетов** — проект включает обновления зависимостей для повышения безопасности и стабильности.
-   **🇷🇺 Полная русификация интерфейса** — все элементы управления, меню и сообщения переведены на русский язык, что делает процесс модификации доступным для русскоязычных пользователей.
-   **📋 Сохранение всех функций оригинала** — Hakchi3 наследует весь мощный функционал Hakchi2-CE, включая:
    -   Добавление дополнительных игр и контента на консоль.
    -   Поддержку различных модулей (hmod) из репозиториев, таких как KMFD mod hub.
    -   Возможность запуска эмуляторов других систем (MAME, Game Boy Advance и др.).
    -   Настройку фильтров, шейдеров и других улучшений изображения.
-   **📜 Соответствие лицензии** — Проект распространяется строго под лицензией **GPL-3.0**, как и оригинальный Hakchi2-CE.

## 📥 Установка и использование

### 📋 Требования

-   Операционная система: **Windows** (рекомендуется Windows 10/11)
-   Консоль: Одна из поддерживаемых ретро-консолей
-   USB-кабель для подключения консоли к компьютеру (используйте качественный кабель, чтобы избежать ошибок)
-   **.NET 8.0 Desktop Runtime** (устанавливается автоматически с программой или может быть скачан отдельно)

### 🚀 Быстрый старт

1.  **Скачайте последнюю версию** из раздела [Releases](https://github.com/Exeqtr-RED/Hakchi3/releases) в этом репозитории.
2.  **Распакуйте архив** и запустите `Hakchi3.exe`.
3.  **Подключите вашу ретро-консоль** к компьютеру с помощью USB-кабеля **в выключенном состоянии**.
4.  **Включите консоль**. Hakchi3 должен автоматически определить устройство.
5.  **Следуйте инструкциям** в русифицированном интерфейсе для добавления игр, установки модулей и настройки консоли.

> 💡 **Подсказка**: Для первого подключения может потребоваться установка драйверов (через встроенный в Hakchi инструмент "Установка драйверов").

<details>
<summary>🔧 Расширенные настройки и Troubleshooting</summary>

-   **Ошибка "Taking too long to boot"**: Чаще всего связана с некачественным USB-кабелем или слабым контактом. Попробуйте использовать другой кабель или порт USB на компьютере.
-   **Проблемы с MAME-играми**: Убедитесь, что вы используете правильные ROM-файлы и настроенные эмуляторы. Некоторые игры могут требовать дополнительных настроек или конкретных версий ядер.
-   **Миграция на новый компьютер**: Для переноса настроек и игр Hakchi на другой ПК, скопируйте папку `hakchi` из директории программы (обычно в `AppData`). Подробности обсуждаются в сообществе.
-   **Установка модулей (hmod)**: Скачайте нужный модуль (например, шейдеры для GBA) и поместите его папку в `user_mods` внутри директории Hakchi. Затем в программе выберите "Установить дополнительные модули".

</details>

## ⚙️ Технические детали и архитектура

Проект Hakchi3 написан на **C#** и **C** с использованием технологии Windows Forms для графического интерфейса.

### 🏗️ Структура репозитория

```
Hakchi3/
├── 📁 .github/                # Конфигурация GitHub (actions, issue templates)
├── 📁 Installer/              # Файлы установщика (NSIS)
├── 📁 Libraries/              # Сторонние библиотеки
├── 📁 NSI/                    # Скрипты NSIS для создания инсталлятора
├── 📁 Scrapers/               # Модули для парсинга обложек и информации об играх
├── 📁 Web Installer/          # Компоненты для веб-установщика
├── 📁 ZIP Files/              # Утилиты для работы с ZIP-архивами
├── 📁 Zipper/                 # Дополнительные инструменты для сжатия
├── 📁 ce-data/                # Данные и конфигурации Community Edition
├── 📁 driver/source/          # Исходный код драйвера для консолей
├── 📁 hakchi_gui/             # Основной графический интерфейс (C#)
├── 📁 libwdi/                 # Библиотека для работы с USB-устройствами
├── 📁 tools/                  # Вспомогательные утилиты
├── 📄 hakchi_gui.sln          # Решение Visual Studio
├── 📄 LICENSE                 # Файл лицензии (GPL-3.0)
└── 📄 README.md               # Этот файл
```

### 🔄 Ключевые изменения по сравнению с оригиналом

1.  **Миграция на .NET8**: Код портирован с более старой версии .NET Framework на современный .NET8, что обеспечивает лучшую производительность, безопасность и кроссплатформенный потенциал (хотя в текущей версии ориентирован на Windows).
2.  **Обновление зависимостей**: Заменены или обновлены потенциально уязвимые NuGet-пакеты, что повышает общую безопасность приложения.
3.  **Локализация**: Все строки интерфейса, сообщения об ошибках и подсказки переведены на русский язык, что достигается через ресурсы (.resx) и отдельные файлы локализации.
4.  **Сборка и распространение**: Проект использует собственный инсталлятор на основе NSIS для удобной установки пользователями.

### 1. Удаление мёртвых методов

GetDocumentsLibraryPath + SHGetKnownFolderPath (Program.cs):
Оба существуют только в месте объявления — git grep по всему репозиторию (включая Libraries/) нашёл ровно 3 совпадения, и все три внутри одной функции: декларация P/Invoke + декларация метода + единственный call изнутри самого метода. Внешних вызовов нет. Метод предназначался для получения пути к библиотеке "Documents" через Windows Known Folder API (GUID 7B0DB17D-9CD2-4A93-9733-46CC89022E7C), но фактически в коде используется Environment.GetFolderPath(Environment.SpecialFolder.MyDocuments) (это видно в Program.cs:184 — там, где настраивается BaseDirectoryExternal). То есть функция была написана как альтернатива, но никогда не была подключена. Это кандидаты на удаление, но я рекомендую проверить сначала — возможно, автор планировал её использовать для случаев, когда MyDocuments перенаправлен через библиотеки.

GenerateStreamFromString (Shared.cs):
Утилита, превращающая строку в MemoryStream. По git grep — 0 вызовов во всём репозитории. Стандартный паттерн new MemoryStream(...) + StreamWriter, но в коде проекта нигде не применяется. Возможно, leftover из ранних версий.

GetDetectedRemoteGameSyncPath (hakchi.cs:268):
Здесь важный нюанс. Рядом (hakchi.cs:275) есть sibling-метод GetRemoteGameSyncPath(ConsoleType consoleType) — он используется в 2 местах (NesApplication.cs:1357, SyncTask.cs:497). А GetDetectedRemoteGameSyncPath() (без параметра, использует текущую консоль) — 0 вызовов. То есть это либо ранняя версия, либо обёртка, от которой отказались в пользу версии с явным параметром. Рекомендую удалить, но это публичный метод — теоретически может быть частью публичного API для внешних потребителей.

### 2. Удаление неиспользуемых файлов

TaskerDebug.cs:
Это реализация интерфейса ITaskerView, которая вместо отображения UI просто пишет в Trace.WriteLine каждое событие (SetState, SetProgress, SetTitle и т.д.). Похоже на debug-заглушку для тестирования Tasker без UI. Никогда не инстанцируется — git grep 'TaskerDebug' находит только класс и его конструктор, ни одного new TaskerDebug() в коде нет. Похоже на leftover отладочного кода.

ApplicationDeploymentWrapper.cs:
Это обёртка над System.Deployment.Application.ApplicationDeployment — ClickOnce API. Использовалась для проверки IsNetworkDeployed / IsFirstRun (типичный паттерн "приложение установлено через ClickOnce?"). Все 4 references — внутри самого файла. ClickOnce не поддерживается в .NET 8 (это .NET Framework-only фича), и после миграции на .NET 8 этот код стал бесполезен — даже если бы его вызвали, он всегда возвращал бы false через applicationDeploymentType == null ветку. Это явный рудимент миграции.

### 3. Удаление неиспользуемых полей

UPDATE_XML_URL (MainForm.cs:34):
URL https://teamshinkansen.github.io/xml/updates/update.xml — это фид автообновления. Поле приватное, единственное упоминание — в закомментированной строке // AutoUpdater.Start(UPDATE_XML_URL); (MainForm.cs:333). Весь блок автoupdater-а закомментирован с пометкой // TEMP: disabled for migration. В hakchi_gui.csproj при этом остался <PackageReference Include="Autoupdater.NET.Official" Version="1.9.2" /> — зависимость не убрали. То есть автoupdater был отключён при миграции на .NET 8, но забытый мусор остался.

InfoRegex (BluetoothControl.cs:36):
Regex @"^\s+([^:]+):\s+(.*)\s*$" — парсит строки вида Key: value (с отступом). Рядом есть 4 sibling-regex: ChangeRegex, NewDelRegex, DeviceRegex, ControllerRegex — все они используются для парсинга вывода bluetoothctl. InfoRegex единственный не используется — видимо, был предназначен для парсинга info-секций устройства, но логика пошла другим путём. Кандидат на удаление, но я бы сначала спросил автора BluetoothControl — возможно, это WIP.

### 4. Удаление классов

**NesMenuElementBaseComparer** — вложенный класс, реализующий IEqualityComparer<NesMenuElementBase>, сравнивающий элементы по Code. По git grep — 0 references во всём репозитории (даже через generic-поиск IEqualityComparer<NesMenuElementBase>). Подобный comparer обычно используется в Dictionary<NesMenuElementBase, T> или HashSet<NesMenuElementBase> или Distinct(...). Но в коде все коллекции используют string Code напрямую как ключ, а не сами объекты. Видимо, класс был написан "про запас" или для ранней версии логики, от которой отказались.

Это самый безопасный кандидат на удаление — вложенный класс, ноль references, не часть публичного API.
